# @gurps-express/ui

Лист персонажа GURPS Express. React + TypeScript + Vite; правила (броски 3d6 и
кубические выражения) берутся напрямую из `@gurps-express/rules-engine`.

## Запуск

```bash
npm run dev            # из корня монорепо (сначала собирает rules-engine)
```

или из `packages/ui`:

```bash`
npm run build --workspace=@gurps-express/rules-engine
npm run dev --workspace=@gurps-express/ui
```

## Контракт данных

UI ожидает готовую отображательную модель листа — `CharacterSheetDto`
(`src/data/types.ts`). Все значения, включая производные характеристики,
уровни умений и стоимости черт, приходят уже вычисленными; UI ничего не
считает по правилам GURPS (единственное исключение — суммирование потраченных
очков для индикатора бюджета).

Источник данных абстрагирован интерфейсом `CharacterSource`
(`src/data/character-source.ts`):

```ts
interface CharacterSource {
  getCharacter(id: string): Promise<CharacterSheetDto>;
}
```

Сейчас источник создаётся фабрикой `createCharacterSource()` в
`src/data/sources/index.ts` и возвращает мок `MockCharacterSource`
(`src/data/mock/bes.ts`, лист «Бес»). Для подключения реального бэкенда
достаточно вернуть из фабрики `HttpCharacterSource`, реализующий тот же
интерфейс, — компоненты менять не нужно.

## Структура

- `src/data/` — контракт DTO, источник данных, моки, суммирование очков;
  `src/data/anatomy.ts` строит DTO куклы из пресета rules-engine
  (`humanoidBlueprint`, B556) и локализует названия зон;
- `src/state/dice.tsx` — контекст бросков поверх `DiceRoller` из rules-engine
  (проверки 3d6, свободные выражения, броски локации попадания, переброс
  отдельных кубиков);
- `src/hooks/` — загрузка персонажа, свёрнутость секций (localStorage),
  тема оформления;
- `src/components/` — секции листа: профиль, характеристики, трекеры ресурсов,
  черты, умения, заклинания, снаряжение, панель бросков, анатомическая кукла;
- `src/components/icons/` — тематические наборы иконок (base / fantasy / scifi),
  выбираются автоматически по активной теме;
- `src/styles/themes/` — три темы × светлый/тёмный режим.

## Темы оформления

Каждая тема — самостоятельный дизайн-язык (не перекраска): свои шрифты,
форма компонентов, текстуры и анимации. Общие правила: компоненты используют
только семантические токены (`--surface`, `--accent`, `--font-display`,
`--font-stat`, ...), темы переопределяют их на `<html data-theme data-mode>`.
Токен `--font-stat` управляет крупными числами (атрибуты, трекеры, вердикты
бросков) — темы подставляют туда моноширинный или антиквенный шрифт.

- **base / Классика** — минимализм «швейцарского листа»: Manrope + JetBrains
  Mono, бумага/графит, один чернильный акцент, плоские карточки с тонкой
  рамкой, аккуратная типографика.
- **fantasy / Фэнтези** — средневековая рукопись: Cormorant (заголовки,
  крупные числа) + PT Serif (текст), пергамент с волокнами, двойные рамки,
  заголовки с ромбовидным окончанием, буквица в имени, костяные кубики с
  «раскатом» вместо тумбла.
- **scifi / Sci-Fi** — бортовой HUD: Exo 2 (заголовки) + Play (текст),
  графит с сеткой и свечением, срезанные углы панелей, скобки-маркеры,
  метки `//` у заголовков, сегментированные шкалы, голографические кубики
  с глитч-анимацией.

Иконки тоже тематические: три набора SVG (`src/components/icons/`) —
тонкий line-art (base), гравировка (fantasy), каркасная голограмма (scifi).

## Возможности листа

- **Поиск и фильтры**: текстовый поиск в каждом разделе + чипы тегов
  (локализация — `src/data/tag-labels.ts`); фильтр тегов комбинируется с
  текстом, контейнеры показываются, если совпадает хоть один потомок.
- **Детальный просмотр черт**: клик по имени черты открывает Drawer —
  полное описание, разбор стоимости (`basePoints × уровни → модификаторы →
  итог`), модификаторы, параметры атаки, заметки и теги.
- **Папки-группы**: дерево преимуществ в моке строится и валидируется
  классом `SheetGroups` из rules-engine (уникальность ссылок, ссылки только
  на известные сущности) — как будет делать будущий API.
- **Редактирование профиля** (сессионно, до появления API): имя, кампания,
  игрок, TL, описание; кастомные поля (добавить/удалить); загрузка портрета
  (файл или drag-and-drop, dataURL, лимит 1.5 МБ).

## Анатомия

Кукла (`AnatomyDoll`) рендерит полигоны из `BodyMap` rules-engine в
нормализованной канве (`viewBox` 1000×2000), поэтому масштабируется под любой
контейнер. Скин зависит от темы: base — line-art, fantasy — гравюра с рамкой,
scifi — штриховой силуэт со сканлайном. Зоны подсвечиваются при наведении
(тултип: имя, броски 3d6, описание), клик фиксирует детали под куклой.
Кнопка «Локация» бросает 3d6 через rules-engine и подсвечивает выпавшую зону
(результат также попадает в историю бросков).

Текущие значения трекеров HP/FP/маны — сессионное состояние UI и в источник
данных не возвращаются.
